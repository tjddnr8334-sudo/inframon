# scripts/bench — 대규모 로버스트니스 벤치

실 교량 데이터 100개는 없다. 대신 **실제로 마주칠 조합을 대량으로 만들어** 파이프라인을
돌리고, 케이스별로 (a) 크래시 (b) 비물리적 출력 (c) 미처리 경계를 잡는다. 목표는 실
교량 진단이 아니라 **소프트웨어 결함 발견**이다.

## robustness_100.py — Tier A (128 케이스, 빠름 ~1분)

형식·규모·좌표원점·데이터 조합을 128 케이스로 만들어 stub 파이프라인 + 프로파일·좌표
(korea_crs)·지오로케이션·잔존수명 로직을 검사한다.

| 그룹 | 케이스 | 검사 |
|---|---|---|
| profile | 8형식 × 5규모 = 40 | 단면높이 물리범위·재료 유효·라멘 고정단 |
| coord | 4원점 × 8위치 = 32 | 왕복 오차 < 0.1m·한국 범위 판정 |
| geoloc | 5입사각 × 4 δh = 20 | NaN/inf 없음·큰 쉬프트 경고 |
| life | 4침하율 × 3한계 × 3기간 = 36 | 음수 없음·열화0 검열·큰침하 유한 |

```bash
python scripts/bench/robustness_100.py          # → data/bench/bench100_result.json
```

## pinn_physical_sanity.py — Tier B (16 케이스, 느림 ~4분)

형식 4종 × 규모 4단으로 **real PINN** 을 돌려 물리 sanity 를 본다.

- **고유진동수 단조성**: 같은 형식에서 span↑ → f1↓ (뻣뻣할수록 고주파)
- EI 물리 범위 · 성분분해 유한 · 크래시 없음

```bash
python scripts/bench/pinn_physical_sanity.py    # → data/bench/bench_pinn_result.json
```

## 이 벤치가 실제로 찾은 것 (2026-07)

- **입사각 0°/비물리값 → 지오로케이션 좌표에 NaN**. `geolocation.py` 가 δh/tan(0)=inf 를
  걸러 쉬프트 0 으로 안전 처리하도록 고침(회귀 테스트 `test_bad_incidence_does_not_produce_nan`).

## 확인된(버그 아닌) 한계

- **대형 교량 EI 포화**: 합성 데모는 분포하중 휨이 약해 `d4≈0` → EI 가 상한(1e14)에 박힌다.
  작은 교량(~25m)은 곡률이 커서 식별된다. 강성열화 잔존수명 채널이 이 포화를 감지해
  "비활성(사유: 포화)" 처리한다 — 실데이터(실측 처짐)가 있어야 EI 추세가 의미를 갖는다.
- **대형 교량 단면높이 상한**: span×형식비가 8m 를 넘으면 상한에 클램프돼 형식별 구분이
  약해진다. 물리적 상한이라 의도된 동작.

## 왜 실 데이터가 아닌가

실 InSAR 100개는 SLC 다운로드 + WSL2 SARvey 처리(교량당 수 시간)가 필요하다. 이 벤치는
**소프트웨어가 다양한 입력에서 견고한지**를 빠르게 확인하는 것이고, 실 교량 진단은 실
Track H5 를 `--import-track-h5` 로 넣어야 한다([실데이터 런북](../../docs/실데이터_런북.md)).
