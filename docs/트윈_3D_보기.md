# 트윈을 3D 로 보기 — 채널·고도·게이트

InSAR 결과를 교량 위에 얹어 3D 로 보는 절차와, **무엇을 색으로 칠해도 되는지**의 기준.

## 1. 산출물

| 파일 | 무엇 |
|---|---|
| `twin_velocity.glb` | LOS 변위속도 채널 — 관측한 값 그대로 |
| `twin_bim.glb` | CRI 채널 — FRAM 위험지수(BMAP 등록용) |
| `*.viewer.html` | 브라우저로 바로 여는 자립형 뷰어(외부 의존 없음) |
| `tileset.json` | 3D Tiles — Cesium·BMAP 탑재용 |
| `*.glb.meta.json` | 점별 값·GlobalId·범례·좌표 근거 |

뷰어는 파일을 더블클릭하면 열린다. 서버가 필요 없다.

## 2. 점을 교량 위에 올리는 두 단계

3D 로 보이게 하려면 **두 보정이 모두** 필요하다. 하나만 하면 점이 다리와 따로 논다.

### ① 고도 — 점을 데크 레벨로

`insar.deck_z.deck_elevation` 이 좋은 원천부터 시도한다(`deck_z.py` 참조).
IFC 부재 상단을 쓸 때 **`element_z_datum` 을 반드시 준다** — IFC 로컬 z 는 대개
원점(지면) 기준이라 그대로 절대고도로 쓰면 원점 표고만큼 어긋난다.

    청양교: 로컬 12.1m 를 절대고도로 쓰면 지면(93m) 아래 → 실제 105.1m

### ② 평면 — 지오코딩 쉬프트 되돌리기

지오코딩은 DEM(지면)을 쓰므로 데크 위 산란체는 **δh/tanθ 만큼 밀려 있다**.
`insar.geolocation.apply_correction` 으로 되돌린다(청양교 평균 12.4m).

밀림의 방향은 교량마다·궤도마다 다르다. `insar.deck_shift.for_bridge` 가 데크 방위와
LOS 기하로 종/횡 성분과 **관측가능성**(|LOS·데크법선|)을 계산한다. 관측가능성이 낮으면
(청양교 0.113 — 데크 방위 83° ≈ LOS 방향) 쉬프트 보정 자체를 검증할 수 없다는 뜻이고,
산출물에 그 사실이 남는다.

## 3. 교축 프로파일은 왜 3D 에 없나

`insar.chainage` 는 점을 교축을 따라 세워 1D 프로파일을 만든다. 이것을 데크 색띠로
3D 에 실으면 "어디가 나쁜가"가 한눈에 보인다 — **데이터가 그것을 지지할 때만.**

`ChainageProfile.is_publishable()` 이 두 가지를 요구한다:

| 기준 | 값 | 왜 |
|---|---|---|
| 커버리지 | ≥ 70% | 결측 구간을 색으로 메우면 안 된다 |
| σ_between / σ_within | ≥ 1.5 | 구간간 차이가 구간내 잡음보다 커야 한다 |

**청양교는 통과하지 못한다:**

    엄격 γ≥0.70   선별 0/48    커버리지 0%
    완화 γ≥0.40   선별 11/48   커버리지 33%
    σ_between 0.764 / σ_within 0.780  →  σ_b/σ_w = 0.98

σ_b/σ_w ≈ 1 은 구간을 나눠도 잡음이라는 뜻이다. 2D 프로파일 그림은 표준오차 막대와
결측구간 표시가 함께 있어 이 상태로도 정직하다. 그러나 같은 값을 3D 색띠로 옮기면
그 단서가 사라지고, **보는 사람이 잡음을 손상 패턴으로 읽는다.** 그래서 막는다.

밀도가 오르면 게이트는 자동으로 열린다. 지금 병목은 γ_temp 중앙값 0.49 —
25 에폭 SBAS 로는 데크 위 산란체가 부족하다. ADI 기반 PS 선별이 그 다음 수단이다
(`snap_backend.amplitude_pairs` → `adi_at_points`; `chainage._quality` 가 ADI 를 우선
사용하므로 트랙에 채워 넣기만 하면 코드 수정 없이 반영된다).

## 4. 만드는 법

    from inframon.insar.gltf_export import (export_insar_gltf, guid_map_from_alignment,
                                            write_web_viewer, write_3dtiles_tileset)

    guids, info = guid_map_from_alignment(proj_h5, "bridge_elements.json",
                                          map_conversion=mc, ifc_crs="EPSG:5186")
    export_insar_gltf(proj_h5, "twin_velocity.glb", value="velocity",
                      element_guids=guids, element_z=info["element_z"],
                      z_source="deck", element_z_datum=93.0)   # ← 원점 표고
    write_web_viewer("twin_velocity.glb")
    write_3dtiles_tileset("twin_velocity.glb")

`value` 는 `velocity`(LOS 속도) · `cri`(FRAM 위험지수, `fram_project` 필요) ·
`cumulative`(누적 LOS). 쉬프트 보정은 프로젝트 h5 의 좌표에 미리 적용해 둔다 —
보정 근거는 `insar` 그룹의 `geolocation_correction` 속성에 남긴다.
