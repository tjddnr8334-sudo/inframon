# 시작하기 — 새 컴퓨터에서 무엇을 받고 어떻게 돌리나

> 이 문서 하나로 **아무것도 없는 PC → 실행**까지 간다. 단계마다 "이게 나오면 성공" 을
> 적어 두었으니 그것만 확인하며 내려가면 된다. 아래 명령은 전부 **깨끗한 가상환경에서
> 실제로 돌려 검증**한 것이다(Windows 11 / Python 3.11.9 기준, 2026-09-03).
>
> 목적별로 필요한 것이 다르다. **1단계만 해도 전체 파이프라인 데모가 돌아간다.**

| 하고 싶은 것 | 필요한 단계 |
|---|---|
| 파이프라인이 뭘 하는지 보기(합성 데모) | 1 |
| 화면(대시보드)으로 결과 보기 | 1 + 2 |
| 실제 위성 데이터로 교량 처리 | 1 + 2 + 3 + 4 |
| 결과를 B-Maps(Pontifex) 플랫폼에 올리기 | 위 전부 + 5 |

---

## 0. 미리 있어야 하는 것

| | 무엇 | 어디서 | 확인 |
|---|---|---|---|
| 필수 | **Python 3.11 이상** | <https://www.python.org/downloads/> (설치 시 *Add python.exe to PATH* 체크) | `python --version` |
| 필수 | **Git** | <https://git-scm.com/downloads> | `git --version` |

> Python 3.11 미만은 안 된다(`requires-python = ">=3.11"`). 3.12·3.13 도 된다.

## 1. 내려받고 설치 — 여기까지만 해도 돈다

```bash
git clone https://github.com/tjddnr8334-sudo/inframon
cd inframon

python -m venv .venv                 # 가상환경(권장 — 시스템 파이썬을 건드리지 않는다)
.venv\Scripts\activate               # Windows      (Linux/macOS: source .venv/bin/activate)

pip install -e .                     # 코어 3개(numpy·h5py·pydantic)만 — 가볍다
```

바로 확인:

```bash
python -m inframon --demo --out demo.h5
```

**이게 나오면 성공** — 합성 데이터로 CV→InSAR→PINN→FRAM 전 구간이 돈 것이다:

```
  통합 인프라 모니터링 — 파이프라인 완료 (CV→InSAR→PINN→FRAM)
  결과 파일      : demo.h5
  측정점/시점    : N=200, M=36
  최대 CRI       : 0.653
  경보 등급      : 경고
```

환경 점검은 언제든:

```bash
python -m inframon --doctor          # 무엇이 되고 무엇이 없는지 한 화면에
```

## 2. 화면으로 보기 (대시보드)

```bash
pip install -e ".[dashboard]"        # streamlit·plotly·folium
python -m streamlit run src/inframon/dashboard/app.py
```

브라우저에서 **http://localhost:8501** — 좌측에서 `project.h5` 를 고르면 InSAR 변위·PINN
구조량·FRAM CRI 를 그래프로 본다. 방금 만든 `demo.h5` 를 골라도 된다.

무거운 계산(실 PINN)까지 쓰려면:

```bash
pip install -e ".[pinn]"             # torch (약 2GB — 시간이 걸린다)
```

## 3. 실데이터를 쓰려면 — 도구 설치

여기서부터는 위성 원자료(SLC)를 실제로 처리한다.

### 3-1. SNAP (InSAR 처리 엔진)

- 내려받기: <https://step.esa.int/main/download/snap-download/> — **SNAP 10 이상, Windows 설치본**
- 기본 경로(`C:\Program Files\esa-snap`)에 설치하면 자동으로 찾는다.

### 3-2. snaphu (위상 언래핑) — **이게 없으면 결과가 무의미하다**

언래핑을 안 하면 변위가 ±13.87mm 에 갇혀 물리적 의미가 없다. Windows 네이티브 빌드가
흔치 않으므로 **WSL 안에 설치**하면 된다 — 프로그램이 알아서 건너가 쓴다.

```powershell
wsl --install -d Ubuntu-22.04                      # WSL 이 없다면(재부팅 필요할 수 있음)
wsl -d Ubuntu-22.04 -- sudo apt-get update
wsl -d Ubuntu-22.04 -- sudo apt-get install -y snaphu
```

확인:

```bash
python -m inframon --insar-tools
```

**마지막 줄이 이러면 성공**:

```
  ✅ 위상 언래핑(SNAP 레인): snaphu /usr/bin/snaphu (WSL:default)
```

없으면 설치 명령을 그 자리에서 알려준다.

### 3-3. 위성자료 조회·계정

```bash
pip install -e ".[search]"           # asf_search — 위성 장면 조회에 필요(가볍다)
```

- **NASA Earthdata** 무료 가입: <https://urs.earthdata.nasa.gov/users/new>
- 다운로드 시 `--earthdata-user` / `--earthdata-pass` 또는 토큰으로 넘긴다.

이걸 넣지 않으면 계획 단계에서 이렇게 나온다(다른 단계는 그대로 진행된다):

```
  ✗ ②④SLC·트랙·프레임    No module named 'asf_search'
```

넣으면 실제 위성 장면이 조회된다:

```
  ✅ ②④SLC·트랙·프레임    ASC path127 frame115 · 42장 · 중심성 +92.7km
```

## 4. 교량 데이터(CSV) — 있으면 추정하지 않는다

프로그램은 제원을 **파일에 있으면 그것을, 없으면 추정**해서 쓴다. 넣을수록 정확해진다.
`data/` 폴더에 두기만 하면 자동으로 찾는다(파일 이름이 아니라 **컬럼**으로 알아본다).

| 파일 | 무엇 | 어디서 |
|---|---|---|
| 전국교량표준데이터 | 연장·폭·보도폭·차로수·형식·준공연도·점검등급·설계활하중 | <https://www.data.go.kr/data/15081953/fileData.do> (무료, CSV 다운로드) |
| 경간수·최대경간이 든 제원 CSV(선택) | **경간수·최대경간** — 표준데이터에 없는 값 | 기관 제공분(KOTSA 매칭 자료 등) |

> **왜 두 번째가 중요한가**: 표준데이터에는 경간수가 없어 최대경간을 연장×비율로 추정한다.
> 그 추정이 광안대교에서 5,565m 로 나왔다(실측 500m). 경간수가 있는 CSV 를 넣으면
> 추정을 쓰지 않는다.

확인 — CSV 를 넣기 전과 후를 ⑪ 교량메타 줄에서 바로 비교할 수 있다:

```
CSV 없음 : ⑪교량메타  기타[추정]·거더교·폭 폭미상·경간미상·산지
CSV 있음 : ⑪교량메타  3종[실측]·slab·연장 90m[실측] · 폭 22.0m[실측]·경간~45m[추정]·산지
                      · 표준데이터 '청양교' 0m
```

항목마다 `[실측]`·`[추정]` 딱지가 붙는다. 위에서 경간만 `[추정]`인 이유는 **표준데이터에
경간수가 없어서**다 — 경간수가 든 CSV 를 넣으면 그것도 실측이 된다.

```bash
python -c "from inframon.bridge_specs_csv import lookup; print(lookup(37.3685, 127.1090, name='정자교').describe())"
# → 5경간 · 최대경간 27m · 연장 108m · 6차로 · PC슬래브교(PCS)
```

### 임의 교량 처리 — 좌표만 있으면 된다

```bash
# 계획만 보기(다운로드·처리 없음) — 무엇을 할지 먼저 확인. 인터넷만 있으면 된다.
python -m inframon --pipeline 36.450655,126.807320 --pipeline-mode plan

# 실행(SLC 취득 → 언래핑 InSAR → 데크 PS/DS → PINN → FRAM → 트윈 → 등록)
python -m inframon --pipeline 36.450655,126.807320 --pipeline-mode full \
    --snap-unwrap --earthdata-user <아이디> --earthdata-pass <비밀번호>
```

이미 SLC 가 있으면 재처리 배치가 빠르다(런북: `docs/재처리_런북.md`):

```bash
python scripts/rerun_unwrap_batch.py --slc "D:/SLC/청양" --out data/chyg \
    --target 36.450655,126.807320
```

**끝나면 반드시 확인** — 이 판정이 ❌ 면 그 수치는 쓰면 안 된다:

```bash
python -m inframon --audit-artifacts data/chyg/project.h5
```

## 5. B-Maps(Pontifex) 플랫폼에 올리기

플랫폼은 별도 패키지(`pontifex-<버전>.tar.gz`)로 받는다. **Docker 필요**.

```bash
# 플랫폼 띄우기 (Ubuntu/WSL)
tar xzf pontifex-1.0.tar.gz && cd pontifex-1.0
./install.sh                          # → http://localhost:38000

# 산출물 올리기 (inframon 쪽)
python -m inframon --bmap-sync --bmap-register --pontifex-token "$TOKEN"
```

감사에 통과한 것만 올라가고, 바뀐 것만 보내며, 결과가 `data/sync_state.json` 에 남는다.
자세한 것은 `docs/BMAP_탑재.md`.

Docker 가 없으면 **무엇이 올라갈지까지는** 확인할 수 있다:

```bash
python -m inframon --bmap-sync --bmap-dry-run
```

## 문제가 생기면

| 증상 | 확인 |
|---|---|
| `python` 이 없다 | 설치 시 *Add python.exe to PATH* 를 놓친 것 — 재설치하거나 PATH 추가 |
| `pip install -e .` 가 실패 | Python 3.11+ 인지(`python --version`), 가상환경이 켜졌는지 |
| 무엇이 안 되는지 모르겠다 | `python -m inframon --doctor` — 되는 것/안 되는 것을 한 화면에 |
| InSAR 처리가 안 된다 | `python -m inframon --insar-tools` — SNAP·snaphu·WSL 상태와 설치 명령 |
| 결과가 이상하다 | `python -m inframon --audit-artifacts <project.h5>` — 6개 열로 사유를 알려준다 |
| 언래핑 실패 메시지 | `docs/재처리_런북.md` §5 에 실제로 겪은 실패 6종의 원인·조치 |
