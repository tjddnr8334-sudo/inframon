# 교량별 실행 결과 — `bridge_run` 배치

유저가 교량을 고르면 **좌표 하나**로 SLC 트랙 → InSAR PS/DS → PINN → CRI → IFC 트윈까지
간다. 여기는 그 실행 결과다. 어느 교량을 보고에 쓸지는 감사 판정과 `결과.md` 의
"적어 둘 것"을 보고 **유저가 정한다** — 파이프라인은 사유를 남기고 멈추지 않는다.

    python scripts/bridge_run.py --batch docs/bridges/batch.json
    python scripts/bridge_run.py --name 청양교 --lat 36.450655 --lon 126.80732 --track <track.h5>

트랙이 없으면 `--track` 을 빼고 좌표만 준다 — ⓪ SLC 검색·다운로드 → SNAP → 언래핑(실패 시
자동 재시도)부터 만든다. 필요한 외부 자격·도구(Earthdata 토큰·SNAP·snaphu)는
`python -m inframon --doctor` 가 알려주고, 토큰은 `--earthdata-save <토큰>` 한 번이면 된다.
⑭ BMAP 전송은 `--pontifex-mock` 모의 서버로 Docker 없이 HTTP 왕복을 확인했다.

각 폴더: `결과.md` · `brief.png`(건기연 형식 4단) · `twin.viewer.html`(더블클릭 3D) ·
`twin_cri.viewer.html` · `*_proxy.ifc` · `project.h5`

입력은 **SLC** 뿐이다(ASF `processingLevel=SLC`). RAW(Level-0)는 파이프라인에 들어가지 않는다.

## ⚠ 교면 전용 재선별 — 위 표의 점·속도는 **교면이 아니다**

위 표와 각 `결과.md` 의 본문 수치는 교량 중심선 **±30 m** 로 고른 점에서 나왔다.
교량 폭이 11~35 m 인데 ±30 m 는 60 m 폭이라 강변 지반이 통째로 섞였다. 확인 방법과
결과는 이렇다.

- `scripts/make_deck_vs_ground.py` — 교량에서 직각으로 떨어진 거리별로 연주기 위상을
  본다. 한강 15개소 중 **11개소**에서 교량 위(0~10 m) 점의 계절 위상이 100~200 m
  떨어진 맨땅과 1.5개월 안으로 같다(가양 −0.2 · 샛강 −0.4 · 성수 +0.3 · 천호 −0.2 …).
  교량이 아니라 주변 지반을 보고 있었다는 뜻이다.
- `scripts/make_deck_fix.py` — 교량마다 다시 고른다. 회랑을 **±폭/2** 로 좁히고,
  코히런스로 지오로케이션 밀림을 되돌리고, 100~400 m 밖 지반 공통성분을 뺀다.
  결과는 교량 폴더의 **`교면전용.json` · `교면전용.png`** 와 `결과.md` 의
  "교면 전용 재선별" 절에 있다. 전체 요약은 `deck_fix_all.json`.

재선별 뒤에는 **16개소 중 13개소의 속도 95% 구간이 0 을 품는다** — 유의한 추세가 없다.
보고서 GNSS 가 있는 5개소의 연주기 위상은 여전히 1.3~5.8개월 어긋난다
(`deck_only_gnss.json`). 지금 자료로는 교면 거동을 봤다고 말할 수 없다.

원인은 통계가 아니라 분해능이다. Sentinel-1 IW 는 지상 5×20 m 이고 데크 폭은 1~2 화소다.
점별 잔차고도 추정도 σ≈26 m 라 형하고(8~25 m)보다 커서, 높이로 교면 점을 가려낼 수도
없다. 고해상도 SAR(TerraSAR-X·KOMPSAT-5 스포트라이트) 또는 데크 위 코너리플렉터가
있어야 이 칸이 채워진다.
