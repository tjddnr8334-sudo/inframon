# 재처리 런북 — 언래핑 포함 SNAP 처리를 **다른 컴퓨터에서** 돌리기

> 기존 track 은 위상 언래핑 없이 만들어져 LOS 가 ±λ/4(13.87mm)에 갇혀 있었다. 그 산출로 낸
> 변위·CRI 는 물리적 의미가 없다(`docs/산출물_감사표.md`). 이 문서는 같은 SLC 로 **언래핑까지**
> 다시 만드는 절차를, 이 개발 PC 가 아닌 곳에서도 그대로 밟을 수 있게 적는다.

## 0. 30초 점검 — 내 PC 에서 되는가

```bash
python -m inframon --insar-tools
```

마지막 줄이 답이다:

```
✅ 위상 언래핑(SNAP 레인): snaphu /usr/bin/snaphu (WSL:default)
❌ 위상 언래핑(SNAP 레인): snaphu 없음 — SNAP 레인은 래핑 위상까지만 (언래핑 필요)
     · WSL(Ubuntu) : wsl -- sudo apt-get install -y snaphu
```

| 필요한 것 | 확인 | 없으면 |
|---|---|---|
| SNAP `gpt` | `python -m inframon --doctor` | [SNAP 설치](https://step.esa.int/main/download/snap-download/) — Windows 네이티브로 충분 |
| `snaphu` | 위 명령 마지막 줄 | Windows 는 **WSL 안에 설치하면 된다** — 프로그램이 알아서 건너간다 |
| SLC(.zip) | 스택 폴더 | `python -m inframon --snap-auto LAT,LON --snap-count 15` |
| 디스크 | 스택당 수 GB | 산출은 교량 ±2km 만 남아 작다 |

> **왜 WSL 로 건너가나**: snaphu 는 Windows 네이티브 빌드가 흔치 않다. `snap_unwrap` 이
> WSL 안의 실행파일을 찾아 경로를 `/mnt/<드라이브>` 로 바꿔 실행한다. 사용자가 신경 쓸 것은
> 없고, 둘 다 없으면 **래핑 산출을 내놓지 않고 멈춘다**.

## 1. 한 스택 재처리 — 가장 단순한 형태

```bash
python scripts/rerun_unwrap_batch.py \
    --slc  "D:/SLC/jeongjagyo" \
    --out  data/rerun_jeongja \
    --target 37.3685405,127.1089983
```

좌표 대신 레시피 폴더를 줘도 된다(레시피가 이미 있으면 이쪽이 안전하다):

```bash
python scripts/rerun_unwrap_batch.py --slc "D:/SLC/jeongjagyo" --recipe data/recipe_jeongja
```

## 2. 여러 스택 — 설정 파일

`configs/rerun_stacks.json.example` 을 복사해 자기 PC 경로로 고친다(`rerun_stacks.json` 은
PC 마다 다르므로 저장소에 넣지 않는다).

```bash
cp configs/rerun_stacks.json.example configs/rerun_stacks.json
# 경로·좌표 수정 후
python scripts/rerun_unwrap_batch.py --stack all
```

## 3. 무엇이 일어나는가

쌍마다 3단계다. 하나라도 실패하면 그 쌍만 실패로 기록하고 다음 쌍으로 간다.

```
① SnaphuExport   코레지 → 간섭도 → 교량 ±2km Subset → snaphu 입력 폴더
② snaphu         conf 가 적어준 명령 그대로 (WSL 이면 건너가서)
③ SnaphuImport   언래핑 위상 → Terrain-Correction → GeoTIFF
```

- **교량 ±2km 만 푼다.** 전 버스트(24,889×1,505 = 3,700만 화소)는 2시간에도 안 끝났고,
  교량 밖은 어차피 ⑨에서 버린다. 잘라서 풀면 **쌍당 약 73초**다.
- 중간에 끊겨도 다시 돌리면 이미 만든 쌍은 건너뛴다(`skip_existing`).
- 산출 GeoTIFF 는 밴드에 이름이 새겨진다(`phase`/`coherence`/`incidence`) — 순서를 외우지
  않아도 하류가 이름으로 찾는다.

## 4. 끝나면 — "정말 풀렸는가"를 확인

배치가 스택마다 자동으로 preflight 를 돌려 출력한다. 직접 볼 때는:

```bash
python -m inframon --check-track data/rerun_f120/track_rerun_f120_unw.h5 \
    --check-target 37.3685405,127.1089983
```

성립한 산출은 이렇게 나온다:

| | 래핑(재처리 전) | 언래핑(재처리 후) |
|---|---|---|
| `|LOS|` 최대 | 13.87mm (= λ/4) | λ/4 를 넘는다 |
| λ/4 초과 점 | 0% | 0 이 아님 |
| 분포 | 균일(바깥절반 ≈50%) | 단봉 |
| preflight | ❌ 차단 | ✅ |

파이프라인까지 태운 뒤에는 감사로 마무리한다:

```bash
python -m inframon --audit-artifacts data/rerun_f120/project.h5
```

`✅ 보고 가능` 이 나와야 대외 인용·플랫폼 전송이 열린다. `--pontifex-push` 도 이 판정을
게이트로 쓰므로, 보고 불가 산출물은 애초에 올라가지 않는다.

## 5. 흔한 실패와 원인

실행으로 겪은 것들이라, 같은 메시지를 만나면 여기를 보면 된다.

| 메시지 | 원인 | 조치 |
|---|---|---|
| `Can't open file coh_*.snaphu.img` | SnaphuExport 가 CORRFILE 이름만 적고 이미지를 안 쓴다 | 자동 처리됨(별도 ENVI 로 내보내 붙인다) |
| `NaN or infinity found in correlation data` | nodata 의 NaN | 자동 처리됨(0 으로 낮춘다) |
| `((Maximum flow) * NSHORTCYCLE) too large` | MCF 초기화 오버플로 | 그래프가 MST 를 쓴다 |
| `Undefined symbol 'UnwPhase_...'` | SNAP 버전마다 밴드 이름이 다르다 | 이름을 지정하지 않는다(정규식 선택) |
| snaphu 가 도는데 결과가 이상하다 | **.hdr 의 byte order 표기가 거짓** | 자동 처리됨(값의 물리 범위로 판정해 뒤집는다) |
| `snaphu 를 찾지 못했습니다` | 도구 없음 | 메시지가 설치 명령을 준다 |

## 6. 새 컴퓨터에 처음 올릴 때

```bash
git clone https://github.com/tjddnr8334-sudo/inframon && cd inframon
pip install -e .
python -m inframon --insar-tools      # 0단계 점검
python -m inframon --start            # ⓪ 시작 탭(안내형 진입점)
```

WSL·SNAP 설치까지 자동으로 하려면 포터블 부트스트랩을 쓴다 — `docs/배포_포터블.md`.
